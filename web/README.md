# web

The TicketLite frontend: Next.js (App Router) built as a **static export** (`web/out`), uploaded to S3 and
served by CloudFront. React Query handles server state, Tailwind CSS handles styling.

- **Dev server:** `pnpm --filter @ticketlite/web dev` → http://localhost:3001 (the API runs on :3000)
- **Build:** `pnpm --filter @ticketlite/web build` → `web/out`
- **Why static export?** No server to run or pay for; CloudFront caches everything. Dynamic pages use query
  strings (`/event?id=...`) because there is no server to render `/event/123` on demand.

## Layout

| Folder | Job |
|---|---|
| `src/app/` | Pages (App Router). Dynamic pages read `?id=` in the browser (static export) |
| `src/features/<feature>/` | Components + React Query hooks per feature: events, auth, bookings, admin, search |
| `src/lib/` | `api-client` (fetch wrapper: token, one refresh-and-retry on 401, correlation id), `token-store` (memory only), `query-client`, `query-keys`, AppSync clients |
| `src/components/` | Shared UI: NavBar, PageHeading (focus on navigation), TextField (accessible errors), FormAlert |
| `src/mocks/` | MSW handlers: used by component tests and by the E2E mock-mode build |
| `src/gql/` | Generated by GraphQL Code Generator (`pnpm --filter @ticketlite/web codegen`), not committed |

**Tests:** `pnpm --filter @ticketlite/web test` (Vitest + React Testing Library + MSW).
**Accessibility:** jsx-a11y strict lint rules, labelled fields with `aria-invalid`/`aria-describedby`, focus moved to
each page's `<h1>`, `aria-live` for seat counts, booking status and search results, axe checks in E2E.
**Performance:** route-level code splitting (admin code never reaches visitors), prefetch on hover, cached API list,
immutable hashed assets. Measure Core Web Vitals with Lighthouse or PageSpeed Insights on the CloudFront URL.
